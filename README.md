# فروشگاه اینترنتی نقشیران

فروشگاه تخصصی تجهیزات نقشه‌برداری نقشیران، ساخته‌شده با Next.js، Drizzle ORM و Cloudflare D1، و اجرا روی Cloudflare Workers با آداپتور OpenNext.

- **مدیریت فروشگاه:** منصور اخوان حریری
- **نشانی:** اصفهان، خیابان استانداری، نبش خیابان فرشادی، فروشگاه مهندسی نقشیران
- **تلفن فروشگاه:** ۰۹۱۳۱۱۴۷۸۹۷

## امکانات

- صفحه‌ی نخست با متن ثابت معرفی فروشگاه شروع می‌شود؛ سپس «محصولات تخفیف‌دار» و «کلیه محصولات» نمایش داده می‌شوند. جست‌وجو، دسته‌بندی و مرتب‌سازی قیمت در بخش کلیه محصولات در دسترس است.
- ۵۰ محصول ارسال‌شده در `src/data/catalog.json` ثبت شده‌اند و همگی عکس نمایشیِ استودیویی محلی دارند (JPG منبع + WebP کم‌حجم). تصویر نمایشی لزوماً عکس دقیق همان مدل نیست و پیش از خرید باید با فروشگاه تطبیق داده شود.
- طبق درخواست فروشگاه، قیمت مبنا برای هر ۵۰ آگهیِ دارای زمان، ۵۰٪ افزایش داده شده است. قیمت نهایی در سایت و سفارش‌ها به تومان است.
- خرید محصول با دکمه‌ی سبز و تمام‌عرض «خرید محصول» برای مهمان، ابتدا صفحه‌ی ورود/ثبت‌نام را باز می‌کند؛ بعد از تکمیل ورود یا ثبت‌نام، قیمت و موجودی همان محصول از سرور بررسی می‌شود، دقیقاً یک عدد به سبد اضافه می‌شود و کاربر به صفحهٔ اصلی برمی‌گردد.
- ثبت‌نام نام و نام خانوادگی، شماره‌ی موبایل ایرانی، نام کاربری انگلیسی و رمز شخصی می‌گیرد. رمز با bcrypt هش می‌شود (حداکثر ۷۲ بایت)؛ شماره در جدول کاربران ذخیره می‌شود و هنگام ثبت سفارش، شمارهٔ گیرنده جدا از شمارهٔ حساب در سفارش ذخیره می‌شود تا فروشگاه بتواند برای هماهنگی تماس بگیرد.
- سبد خرید در مرورگر نگهداری می‌شود؛ قیمت نهایی و موجودی هنگام ثبت سفارش دوباره از پایگاه داده بررسی می‌شوند.
- فیش واریزی در مرورگر کوچک‌سازی می‌شود (حداکثر ۱٬۶۰۰ پیکسل، JPEG و هدف زیر ۱٬۵۰۰٬۰۰۰ کاراکتر base64) تا از سقف ۲ مگابایت هر ردیف D1 عبور نکند؛ عکس‌های بزرگ گوشی پیش از ارسال فشرده می‌شوند.
- پیگیری سفارش، ثبت تصویر فیش واریزی، ارسال اعلان به تلگرام (در صورت تنظیم توکن و شناسه‌ی ادمین) و مشاهده‌ی حساب کاربری در دسترس هستند. تصویر نمایشی کارت بانک ملی، شماره کارت `6037997327623303` و دکمهٔ کپی در اطلاعات واریز نمایش داده می‌شوند؛ نام و تلفن گیرنده از حساب پر می‌شوند و برای هر دو روش تحویل اجباری و قابل اصلاح‌اند. در تسویه، تحویل حضوری با نمایش کامل نشانی فروشگاه یا ارسال با پیک پس از پیش‌پرداخت انتخاب می‌شود و توضیح اختیاری مشتری نیز برای فروشنده ذخیره می‌گردد.
- نوار پایینی سبد خرید پس از انتخاب کالا تعداد، مبلغ کل و دکمه‌ی «مشاهده سبد خرید» را همیشه نشان می‌دهد. کاربر مهمان با کلیک روی افزودن به ورود/ثبت‌نام می‌رود و بعد از ورود دقیقاً یک عدد از همان محصول به سبدش برمی‌گردد.
- پنل فروشنده در `/admin` سفارش‌های همه‌ی خریداران را با اقلام، مبلغ، فیش واریزی، نام کاربری، تلفن، آدرس، توضیح مشتری و روش تحویل نمایش می‌دهد. فروشنده می‌تواند فیش را تأیید یا رد کند، یادداشت تماس ثبت کند و از همان پنل با لینک تماس یا واتساپ با مشتری ارتباط بگیرد. ورود با حساب فروشنده از همان `/login` انجام می‌شود؛ فقط فروشنده لینک «پنل فروشگاه» را در بالای سایت می‌بیند. رمز اولیه را پیش از انتشار عمومی در تب «امنیت حساب» تغییر دهید؛ تغییر رمز تمام نشست‌های قبلی فروشنده را باطل می‌کند.
- تب مدیریت محصولات: افزودن، جست‌وجو با کد یا نام، ویرایش نام/کد/عکس/توضیحات/قیمت/دسته/موجودی، تعیین درصد تخفیف و بایگانی یا بازیابی. عکس از فایل بارگذاری یا با نشانی HTTPS ثبت می‌شود. بایگانی، سابقه سفارش‌ها را حذف نمی‌کند.
- تب پیام به مشتری: ارسال پیام به نام کاربری، مشاهده پیام‌های ارسال‌شده و وضعیت خواندن؛ مشتری پیام را در `/messages` با عنوان «فروشنده نقشیران» می‌بیند. شمارنده پیام جدید در سربرگ هر ۳۰ ثانیه و هنگام بازگشت به پنجره تازه می‌شود.
- APIهای فروشنده علاوه بر کنترل صفحه، نقش حساب را در سرور بررسی می‌کنند. فرم عمومیِ حاوی رمز پیش‌فرض حذف شده، ثبت‌نام با نام رزروشدهٔ `admin` ممنوع است و هیچ حساب مشتری بر اساس نام کاربری به مدیر ارتقا نمی‌یابد. نشست‌های قدیمی مدیریت یک‌بار باطل می‌شوند؛ ورود محدودیت تلاش و درخواست‌های تغییردهنده کنترل مبدأ دارند.
- کنترل تصویر کاتالوگ: دستور `npm run catalog:images` همه‌ی کدهای کاتالوگ را بررسی می‌کند؛ URL سفارشی خراب یا محصولی که تصویر ندارد ابتدا از تصویر کاتالوگ و در نهایت از `public/images/catalog/placeholder.svg` استفاده می‌کند تا هیچ کارت محصولی تصویر شکسته نداشته باشد.

## راهنمای این به‌روزرسانی

راهنمای فروشنده و نکات انتشار در [docs/SELLER_GUIDE_FA.md](docs/SELLER_GUIDE_FA.md) است. این تغییرات خودبه‌خود روی سایت اصلی منتشر نمی‌شوند؛ ابتدا build و deploy نسخه جدید لازم است. ارتقای D1 در اولین درخواست، با حفظ اطلاعات قبلی انجام می‌شود؛ **برای این به‌روزرسانی نیازی به اجرای دوبارهٔ seed یا همهٔ migrationهای قدیمی نیست.**

## پایگاه داده (Cloudflare D1)

- نام دیتابیس: `d1_naghshiran`
- شناسه: `96fcda7f-4093-47d2-b210-75b749658c65`
- binding در `wrangler.jsonc`: `DB`

ساختار جداول در `src/db/schema.ts` (SQLite) تعریف شده و فایل‌های SQL آن در پوشه‌ی `drizzle/` قرار دارند. ستون‌های قیمت از نوع INTEGER 64 بیتی هستند و قیمت‌های میلیاردی تومان را بدون سرریز نگه می‌دارند.

### یک‌بار پیش از اولین دیپلوی

```bash
npm ci
npx wrangler login        # ورود به حساب Cloudflare
npm run db:push           # ساخت جداول روی D1 واقعی
npm run db:seed           # واردکردن ۵۰ محصول (با ۵۰٪ افزایش قیمت)
```

اجرای دوباره‌ی `db:seed` محصولات موجود را بازنویسی نمی‌کند.

## راه‌اندازی محلی

```bash
npm ci
cp .env.example .dev.vars   # SESSION_SECRET را تنظیم کنید
npm run db:push:local
npm run db:seed:local
npm run preview             # اجرای واقعی Worker با D1 محلی روی http://localhost:8787
# یا برای توسعه‌ی سریع:
npm run dev
```

## متغیرهای محیطی

نمونه در `.env.example` است. دیگر به `DATABASE_URL` نیازی نیست؛ اتصال از طریق binding `DB` برقرار می‌شود.

```env
SESSION_SECRET=یک-رشته-تصادفی-طولانی-حداقل-۳۲-کاراکتر
NEXT_PUBLIC_SITE_URL=https://your-domain.example
TELEGRAM_BOT_TOKEN=
TELEGRAM_ADMIN_CHAT_IDS=
```

> **نکته مهم (رفع باگ ورود):** دیگر تنظیم `SESSION_SECRET` الزامی نیست. اگر این متغیر تنظیم نشده باشد (یا کوتاه‌تر از ۳۲ کاراکتر باشد)، برنامه به‌صورت خودکار یک کلید تصادفی قوی می‌سازد و در جدول `app_settings` همان دیتابیس D1 نگه می‌دارد تا ورود و ثبت‌نام بدون هیچ پیکربندی دستی کار کند. تنظیم صریح `SESSION_SECRET` (حداقل ۳۲ کاراکتر) همچنان مجاز است و بر کلید خودکار اولویت دارد؛ در این صورت آن مقدار باید ثابت بماند تا نشست‌های کاربران باطل نشوند.

## دیپلوی روی Cloudflare

این پروژه با **Next.js + OpenNext + Cloudflare Workers + D1** تنظیم شده است. در Cloudflare Workers Builds، برای جلوگیری از ورود OpenNext به حلقه‌ی بازگشتی، دستور build اصلی پروژه همان `npm run build` است و این دستور در `package.json` مستقیماً `opennextjs-cloudflare build` را اجرا می‌کند؛ OpenNext نیز از `buildCommand` موجود در `open-next.config.ts` برای اجرای `npm run build:next` استفاده می‌کند.

تنظیمات پیشنهادی Workers Builds:

| تنظیم | مقدار |
|---|---|
| Build command | `npm run build` |
| Deploy command | `npm run deploy` |
| Root directory | `/` |

فایل `wrangler.jsonc` نیز Worker، assetها و binding دیتابیس D1 با نام `d1_naghshiran` و شناسه جدید را تعریف می‌کند.

در **Settings → Variables and Secrets** می‌توانید `SESSION_SECRET` را (حداقل ۳۲ کاراکتر) تنظیم کنید؛ اما الزامی نیست و در صورت عدم تنظیم، کلید نشست به‌صورت خودکار در D1 ساخته و نگهداری می‌شود (بخش متغیرهای محیطی). در صورت استفاده از اعلان تلگرام، `TELEGRAM_BOT_TOKEN` و `TELEGRAM_ADMIN_CHAT_IDS` را وارد کنید.

در Workers Builds، `npm run build` یک‌بار فایل‌های `.open-next` را می‌سازد و `npm run deploy` همان خروجی آماده را منتشر می‌کند؛ بنابراین build سنگین دوباره تکرار نمی‌شود. برای ساخت و انتشار یک‌مرحله‌ای از سیستم محلی، دستور `npm run deploy:fresh` را اجرا کنید. فایل `.npmrc` نیز اسکریپت‌های نصب لازمِ `esbuild`، `workerd` و `unrs-resolver` را صریحاً تأیید می‌کند تا npm جدید در Cloudflare باینری‌های موردنیاز build را مسدود نکند. هشدارهای `deprecated` وابستگی‌های غیرمستقیم خطای build نیستند.

> جدول‌ها و کاتالوگ محصولات در اولین درخواست به دیتابیس به‌صورت خودکار ساخته می‌شوند (`src/db/index.ts`)؛ اجرای دستی `db:push` و `db:seed` دیگر الزامی نیست. همین مرحله، دیتابیس قدیمی را فقط یک‌بار و بدون حذف سفارش‌ها از کدهای ۹۶xxx به بازهٔ ۲۰۰–۲۴۹ منتقل می‌کند و شناسه، قیمت، موجودی و عکس سفارشی محصول را حفظ می‌کند.

## تصاویر محصولات و تخفیفات ویژه

تمام ۵۰ محصول عکس نمایشیِ استودیویی (JPG منبع + WebP کم‌حجم) و مسیر fallback دارند. تصویرهای نمایشی عکس واقعی کالای فروشی یا تضمین ظاهر دقیق همان مدل نیستند و کارت‌ها این موضوع را شفاف اعلام می‌کنند. مسیرها در `src/data/catalog-images.json` ثبت شده‌اند. اگر عکس سفارشی نامعتبر باشد، کارت و سبد ابتدا تصویر WebP کاتالوگ و در صورت خرابی آن، SVG همان محصول را نمایش می‌دهند (SVGها فقط به‌عنوان fallback نگه داشته شده‌اند).

برای افزودن عکس به محصولی که هنوز ندارد، فایل `public/images/catalog/<کد>.jpg` را بگذارید و دستور زیر را اجرا کنید؛ عکس‌های قبلی دست‌نخورده می‌مانند:

```bash
npm run catalog:optimize
```

پس از افزودن یا جایگزینی JPG/PNG/SVG، `npm run catalog:optimize` را اجرا کنید تا نسخه‌های WebP از نو ساخته و manifest هم‌زمان به‌روز شود. عکس سفارشی فروشنده در دیتابیس حفظ می‌شود؛ مسیرهای قدیمی تصاویر کاتالوگ از manifest جدید استفاده می‌کنند.

ترتیب ثابت صفحه: متن معرفی فروشگاه ← «محصولات تخفیف‌دار» ← «کلیه محصولات». متن معرفی دقیقاً عنوان و توضیح درخواستی فروشگاه را دارد و با جست‌وجو یا تغییر دسته‌بندی حذف نمی‌شود. بخش تخفیف‌ها نیز مستقل از فیلترهای کلیه محصولات است. کد ۵۰ محصول به‌صورت پیوسته از **۲۰۰ تا ۲۴۹** است؛ کد دیگر روی عکس قرار نمی‌گیرد و در متن توضیحات محصول نمایش داده می‌شود. نرخ تخفیف چهار محصول در `src/data/special-offers.json` تنظیم شده: کد ۲۱۲ با ۱۵٪ و کدهای ۲۱۷، ۲۲۳، ۲۳۴ با ۱۰٪. این درصدها تنظیم پیشنهادی این نسخه‌اند و پیش از انتشار باید توسط فروشگاه تأیید شوند. قیمت پایهٔ دیتابیس تغییر نمی‌کند؛ قیمت فروش در ویترین، سبد و سرور سفارش از یک تابع مشترک محاسبه می‌شود.

## اطمینان از ثبت سفارش

سفارش، اقلام و رزرو موجودی در یک batch اتمی D1 ثبت می‌شوند. فیش واریزی (data URL) در همان ردیف `orders` ذخیره می‌شود؛ D1 سقف ۲ مگابایت برای هر رشته/ردیف دارد، پس سرور تصاویر بیش از ۱٬۸۰۰٬۰۰۰ کاراکتر base64 را رد می‌کند و مرورگر قبل از ارسال آن‌ها را فشرده می‌کند. صفحه‌های لیست سفارش و پولینگ وضعیت، فیش را دریافت نمی‌کنند. کلید درخواست مانع ساخت سفارش تکراری در تلاش مجدد می‌شود. با رد سفارش، موجودی یک‌بار آزاد می‌شود؛ سفارش ردشدهٔ این نسخه قابل بازگشت به pending/approved نیست و برای خرید مجدد سفارش جدید بسازید. سفارش‌های قدیمی قبل از این نسخه مشمول رزرو جدید نمی‌شوند. شمارهٔ گیرنده، شمارهٔ حساب را تغییر نمی‌دهد.

SQL افزایشی در `drizzle/0001_safe_checkout.sql` و نسخهٔ زمان اجرا در `src/db/checkout-schema.ts` یکسان هستند؛ اطلاعات قبلی حذف یا بازنویسی نمی‌شوند.

## تست

```bash
npm test                    # ۱۵ تست منطق/تصاویر + ۶ تست SQLite
npm run typecheck
npm run lint
npm run build               # ساخت Worker واقعی
python3 tests/api-smoke.py   # فقط روی سرور محلی؛ دادهٔ تست ایجاد می‌کند
npx playwright install chromium
npm run test:catalog         # ترتیب بخش‌ها، فیلترها، موبایل/دسکتاپ و fallback عکس؛ بدون ثبت سفارش
npm run test:e2e             # فقط دیتابیس محلی؛ ثبت‌نام و سفارش آزمایشی می‌سازد
```

تست مرورگر به Chromium و کتابخانه‌های سیستم آن نیاز دارد. دستورهای integration را روی فروشگاه واقعی اجرا نکنید.

## دستورهای مفید

```bash
npm run dev          # توسعه
npm run typecheck    # بررسی TypeScript
npm run lint         # بررسی ESLint
npm run build        # ساخت production
npm run preview      # اجرای Worker با D1 محلی
npm run deploy       # انتشار خروجی build موجود روی Cloudflare Workers
npm run deploy:fresh # ساخت و انتشار یک‌مرحله‌ای از سیستم محلی
npm run db:generate  # ساخت فایل SQL از schema
npm run db:push      # اعمال schema روی D1 (--local برای محلی)
npm run db:seed      # واردکردن کاتالوگ پایه (--local برای محلی)
```
