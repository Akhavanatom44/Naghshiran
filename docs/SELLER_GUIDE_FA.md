# راهنمای پنل فروشگاه و خرید

## ورود امن فروشنده

1. از «ورود» معمولی سایت با حساب `admin` وارد شوید؛ اطلاعات ورود دیگر هیچ‌جا به بازدیدکننده نمایش داده یا در فرم از پیش پر نمی‌شوند.
2. بعد از ورود، «پنل فروشگاه» در بالای سایت، در موبایل و دسکتاپ، ظاهر می‌شود.
3. **رمز اولیهٔ درخواستی ساده و از قبل افشاشده است؛ قبل از عمومی‌کردن سایت، در «امنیت حساب» آن را تغییر دهید.** داشتن لینک مخفی جای رمز قوی را نمی‌گیرد. رمز جدید حداقل ۱۲ نویسه و حداکثر ۷۲ بایت است. تغییر رمز، نشست‌های قبلی فروشنده را باطل می‌کند.
4. کاربران عادی حتی با واردکردن نشانی `/admin` یا فراخوانی مستقیم APIها اجازهٔ مدیریت ندارند. نام کاربری رزروشده را نمی‌توان از مسیر ثبت‌نام ساخت و حساب مشتری خودکار به مدیر ارتقا نمی‌یابد.

## محصولات

- «افزودن محصول»: کد یکتا، نام، قیمت پایه به تومان، موجودی، دسته‌بندی، جزئیات و عکس را تکمیل کنید.
- عکس JPEG، PNG یا WebP تا ۱۵ مگابایت پذیرفته و پیش از ارسال فشرده می‌شود. تصویر نهایی به‌صورت جداگانه در D1 نگهداری می‌شود؛ URL عمومی آن در محصول ثبت می‌شود. نشانی HTTPS نیز قابل استفاده است.
- با تیک «این محصول تخفیف دارد»، درصد ۱ تا ۹۹ را وارد کنید. قیمت نهایی پیش‌نمایش دارد و همان قیمت در فروشگاه، سبد و سفارش معتبر است. برداشتن تیک تخفیف، تخفیف قبلی را واقعاً حذف می‌کند.
- کد فارسی یا انگلیسی، نام یا دسته‌بندی را جست‌وجو و «ویرایش» را انتخاب کنید. همهٔ مشخصات قابل تغییر هستند.
- «حذف» پس از تأیید، محصول را از فروشگاه خارج می‌کند، ولی آن را برای حفظ تاریخچه سفارش‌ها بایگانی می‌کند. از «ویرایش / بازیابی» و تیک «فعال» می‌توان آن را برگرداند.
- اگر در حین ویرایش، موجودی یا مشخصات محصول تغییر کند، ذخیرهٔ نسخهٔ قدیمی رد می‌شود؛ محصول را دوباره باز کنید تا موجودی تازه بازنویسی نشود.

## سفارش‌ها و پیام‌ها

- سفارش را انتخاب کنید تا اقلام، مبلغ، فیش، مشخصات حساب و گیرنده، روش تحویل و توضیح مشتری نمایش داده شوند. تأیید یا رد فیش و ثبت یادداشت در همین بخش است.
- از داخل جزئیات سفارش مستقیماً به همان مشتری پیام بدهید؛ یا در تب «پیام به مشتری» نام کاربری را وارد کنید.
- تاریخچهٔ ارسال، وضعیت خواندن و دریافت پیام‌های قدیمی‌تر در دسترس است.
- مشتری در بخش «پیام‌ها» و صفحهٔ حساب پیام را با عنوان «فروشنده نقشیران» می‌بیند. بازکردن پیام آن را خوانده‌شده می‌کند. پیام‌ها فقط به گیرندهٔ همان پیام نمایش داده می‌شوند.
- این قابلیت پیام داخل سایت است، نه پیامک یا اعلان مرورگر. مشتری برای دیدن پیام باید به سایت وارد شود.

## خرید و پرداخت

- روی هر محصول دکمهٔ سبز «خرید محصول» زیر قیمت و واحد تومان قرار دارد. اولین انتخاب تبدیل به تعداد ۱ می‌شود؛ مثبت سمت راست و منفی سمت چپ است. کاهش تا صفر، دکمهٔ خرید را برمی‌گرداند.
- کلیک مهمان او را به ورود/ثبت‌نام می‌برد؛ پس از موفقیت، یک عدد از همان محصول با قیمت و موجودی تازه انتخاب می‌شود و به فروشگاه برمی‌گردد.
- نوار پایین تعداد و مجموع قیمت را همراه «مشاهده سبد خرید» نمایش می‌دهد.
- در هر دو روش «پیک» و «حضوری»، اطلاعات واریز شامل تصویر نمایشی کارت بانک ملی و شمارهٔ قابل کپی `6037997327623303` است. تصویر هیچ CVV2 یا تاریخ انقضایی ندارد و صرفاً برای نمایش اطلاعات واریز است.
- نام و تلفن از حساب کاربری پر می‌شوند؛ اصلاح مشخصات گیرنده ممکن است. هر دو فیلد در مرورگر و سرور الزامی هستند. اصلاح آن‌ها مشخصات همان سفارش را تغییر می‌دهد، نه اطلاعات حساب را.
- توضیحات مشتری اختیاری، آدرس برای پیک الزامی و فیش برای هر دو روش الزامی است. هشدار ستاره‌دار، مشتری را به بررسی تلفن پیش از ثبت سفارش راهنمایی می‌کند.
- نشانی حضوری: اصفهان، خیابان استانداری، نبش خیابان فرشادی، فروشگاه مهندسی نقشیران.
- تماس برای سؤال درباره واریز و پیگیری بعد از ثبت: شمارهٔ موجود فروشگاه، ۰۹۱۳۱۱۴۷۸۹۷.

## انتشار و داده‌ها

- build: `npm ci && npm run build`؛ انتشار طبق تنظیمات فعلی پروژه با `npm run deploy` و دسترسی مجاز Cloudflare انجام می‌شود. در این تغییرات، دادهٔ واقعی فروشگاه تغییر یا نسخه‌ای روی حساب Cloudflare منتشر نشده است.
- D1 به‌صورت افزایشی در اولین درخواست ارتقا پیدا می‌کند: `discount_percent` محصولات، `session_version` کاربران، جدول پیام‌ها، عکس‌های محصول و محدودیت تلاش ورود. فایل مرجع SQL: `drizzle/0005_seller_panel.sql`.
- نیازی به reset، reseed یا بازپخش migrationهای قدیمی نیست. اسکریپت قدیمی `db:push` برای دیتابیس تازه است و روی دیتابیس موجود ممکن است به جدول/ستون تکراری برخورد کند.
- تخفیف‌های قبلی برای محصولاتی که هنوز فروشنده ویرایش نکرده حفظ می‌شوند؛ مقدار صریح صفر تخفیف را غیرفعال می‌کند.
- نشست‌های مدیریتِ پیش از این اصلاح امنیتی یک‌بار باطل می‌شوند. اگر حساب رزروشدهٔ `admin` قبلاً مشتری بوده باشد، برنامه عمداً آن را ارتقا نمی‌دهد؛ مالک باید نقش حساب صحیح را از مسیر مدیریتی مورد اعتماد دیتابیس بررسی کند.
- پیش از انتشار از D1 نسخهٔ پشتیبان بگیرید، رمز اولیه را عوض کنید و binding `DB` را بررسی کنید. عکس‌های بارگذاری‌شده در D1 ذخیره می‌شوند؛ برای کاتالوگ‌های بسیار بزرگ بهتر است ذخیره‌سازی شیء مانند R2 جداگانه طراحی شود.

## آزمون‌ها

```bash
npm run typecheck
npm run lint
npm test                  # آزمون‌های واحد و تراکنش‌های SQLite
npm run test:e2e          # ورود/ثبت‌نام، انتخاب مهمان و خرید
npm run test:seller       # کنترل دسترسی، محصولات، پیام‌ها، پرداخت و نمایش موبایل
npm run build             # خروجی Next و Worker
```

آزمون‌های مرورگر به Chromium نصب‌شده در Playwright یا متغیر `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` نیاز دارند. `test:seller` عمداً فقط روی localhost اجرا می‌شود و داده‌های آزمایشی می‌سازد؛ آن را روی دیتابیس اصلی اجرا نکنید. برای رمز تغییریافتهٔ فروشنده در تست محلی از `TEST_ADMIN_PASSWORD` استفاده کنید.
